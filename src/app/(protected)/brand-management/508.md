## Screen Reader Testing Notes

- All dialogs use **Radix UI Dialog** primitives which provide `role="dialog"`, `aria-modal="true"`, focus trap, and `Escape` key dismissal out of the box.
- `disablePointerDismissal={isSubmitting}` prevents accidental close during active form submission.
- `ActionButtonCell` uses a shadcn `Tooltip` pattern — ensure tooltip content is also exposed as `aria-label` so it works when tooltips are suppressed.
- The Campaigns column button currently has no navigation target. The `aria-label` correctly describes the intent; once the feature is wired, verify the interaction still satisfies WCAG 2.4.4.

## Known Limitations

- **Campaigns button** (`brand-table-columns.tsx`): The button is interactive but has no action yet (placeholder). It is labelled correctly; once wired to a route or panel, re-verify focus management.
- **Colour contrast on gradient buttons**: The green gradient CTA in `activate-brand-dialog.tsx` (`from-[#10B981] to-[#059669]`) should be tested against the white text (`#FFFFFF`) at both gradient extremes. WCAG 1.4.3 requires ≥ 4.5:1 for normal text. `#059669` on white yields ~4.5:1 — borderline. Recommend using the darker stop (`#047857`) as the base for body text if updated.
- **`FormInputField` / `FormComboboxField` internals**: The error `aria-describedby` wiring is assumed to be handled inside those shared components. Verify that each error `<p>` has a unique `id` matching the input's `aria-describedby` attribute.
